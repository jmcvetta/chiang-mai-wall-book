# GitHub Repository Configuration

Manages `jmcvetta/chiang-mai-wall-book` itself: merge settings, the ruleset on
`master`, security features, the standard issue labels and the non-secret
release App ID.

This directory is validated offline in CI. **Applying it and committing the
state is a human step** (#30); an agent never applies and needs no admin
credentials.

## What it declares

- `github_repository.this` -- squash-only merging (PR title as subject, PR body
  as message), auto-merge on, branches deleted after merge, public visibility
  unchanged, secret scanning and push protection kept enabled.
- `github_repository_vulnerability_alerts.this`,
  `github_repository_dependabot_security_updates.this` -- Dependabot alerts and
  automated security updates.
- `github_workflow_repository_permissions.this` -- read-only default token that
  cannot create or approve pull requests; the release App does that work.
- `github_repository_ruleset.master` -- pull request required (0 approvals,
  conversations resolved), required checks exactly `Checks` and `Release
  Projection` with the strict up-to-date policy, linear history, no deletion or
  force push. One bypass actor: repository admins, pull-request mode only.
  `actor_id 5` is GitHub's built-in admin role.
- `github_issue_label.*` -- the seven standard labels. Nothing else is
  declared, so stock and unrelated labels survive.
- `github_actions_variable.release_bot_app_id` -- `RELEASE_BOT_APP_ID`, read by
  `release-please.yml`. Its value is the input `release_bot_app_id`.

## Secrets and state

Never put a secret in configuration or state. `RELEASE_BOT_PRIVATE_KEY` stays a
GitHub secret set by hand; it is not a Tofu input, output or state value. State
is local (`terraform.tfstate`) and committed, and holds only repository
metadata. No remote state, no cloud infrastructure.

## Required checks

Each ruleset context is the `name:` of an Actions job: `Checks` is job `checks`
in `ci.yml`, `Release Projection` is job `release-projection` in
`release-projection.yml`. Renaming a job without editing `ruleset.tf` leaves a
required check nothing reports and blocks every pull request. Both workflows
already report on `master`, so both can be required now; require a new
context only after its workflow has reported there. Neither workflow may gain a
`paths:` filter.

## Validation

```bash
make -C infra/github check-infra   # fmt -check, init -backend=false, validate
```

CI runs these as steps in the `Checks` job, without credentials.
`.terraform.lock.hcl` is generated by `tofu init`; never edit it by hand.

## Apply (human, #30)

```bash
cd infra/github
export GITHUB_TOKEN=$(gh auth token)              # admin on the repository
export TF_VAR_release_bot_app_id=<numeric App ID>
tofu init
IMPORT_RELEASE_BOT_APP_ID=1 ./import.sh           # drop the variable if RELEASE_BOT_APP_ID does not exist yet
tofu plan
tofu apply
```

Commit `terraform.tfstate` afterwards. The pull request that adds this stack
stays a draft until that state is committed, so code and state merge together.

`import.sh` adopts the repository, vulnerability alerts, Dependabot security
updates and every existing label (`epic`, `task`, `human`, `story`, `bug`,
`proposal`), and optionally the App ID variable. `research` does not exist and
is created by the apply.

### Reading the plan

Expected: updates in place (repository merge settings, `bug` and `proposal`
colour/description), creations (ruleset, workflow permissions, `research`, any
not-yet-existing variable or Dependabot resource). **There must be no destroy,
replace (`-/+`, "forces replacement"), rename, visibility change or unrelated
setting change.** A plan that would recreate the repository or a label means a
missing import: stop, import it, plan again. Dropping stock labels cannot come
from this stack; if it appears, something is wrong.

## App credential setup

Install the release GitHub App on the repository, set the secret
`RELEASE_BOT_PRIVATE_KEY` by hand, and pass the App's numeric ID as
`TF_VAR_release_bot_app_id`. `release-please.yml` switches to the App once
`RELEASE_BOT_APP_ID` is set, so set the variable and key together.
